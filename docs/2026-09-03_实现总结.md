## 0 结论速览

1. **无真值建图链路已通**：Replica RGB-D → ORB-SLAM3（全程不给 GT）→ 估计位姿直接训 semsplat，几何重建与"正确约定 GT 位姿"的基线差距 **< 0.2 dB PSNR**；ORB 轨迹 ATE RMSE **4.1 cm / 0.51%**。
2. **语义质量随教师升级取得实质改善**：CLIP patch(认不对) → **SAM 整对象掩码+CLIP（肉眼确认显著更准，top-2 类间余量 ~1.5–2×）**。LSeg 稠密教师因特征与 CLIP base 文本不对齐而中止；SuperClip(SLIC) 明显好于 CLIP 但仍有"碎片≠对象"上限；背景类/阈值后处理无效。
3. **量化（已修正内参后）**：office0（无真值位姿 + SAM 语义）**fx320·20k 重建 PSNR ≈ 39 dB、13 类 mIoU 0.206**；曾用错内参 fx577（ATE 3% vs 0.05%）把几何拉长、重建仅 ~29 dB——真内参为 fx320/FOV90。
4. **剩余瓶颈**：细对象/稀有类的开放词识别、SAM 网格稀疏(3–7 块/帧)、合成/自录域差异；语义 3D 交互 viewer 尚未完全验证。
5. **（2026-09-04）AMG 教师的天花板丢失 = CLIP 对"同色平涂面"的混叠，非欠拟合/非 bug**；查询时几何法向先验把 20k AMG 的 ceiling 从 .025 收回 .498（mIoU .194→.231，物体类与 RGB 不动）——新管线（AMG + 足迭代）拟默认开（前置：world-up 自动估计）；**离线清理叠加仅评估到 .286，暂不纳入实施**。详见 `docs/2026-09-04_几何判向修复天花板与离线清理评估.md`。

## 1 无真值位姿建图

### 1.1 数据（Replica Demo）
- `data/replica_demo/frames/`：500 帧 `color/`(1296×968 jpg)、`depth/`(640×480 uint16 **mm**)、`pose/<i>.txt`(16 个 float=c2w)、`intrinsic/`。
- **color 与 depth 光心重合、仅内参/分辨率不同**（`extrinsic_*.txt` 为单位阵）→ 注册只需按内参一次仿射重采样；估计位姿对 color/depth 同时成立。

### 1.2 链路（新增 `scripts/orb_slam/`，**semsplat 本体零改动**地复用数据转换）
```
RGB-D(无GT)
  → replica_prep_orb.py : depth 用 cv2.remap(INTER_NEAREST) 注册到 color 网格(1296×968)，
                         生成 data/orb_replica/{rgb(软链),depth(mm),assoc.txt,orb.yaml}
  → run_orb.sh : ORB-SLAM3 Examples/RGB-D/rgbd_tum → CameraTrajectory.txt(TUM)（运行目录=ORB 仓库）
  → traj_to_scene.py : TUM→每帧 4×4，做相机轴换算 c2w_gl=[R_wc·diag(1,-1,-1)|t_wc]，
                      输出 data/replica_orb_est/frames/{pose,color/depth 软链,intrinsic 拷贝}
  → (现成) replica_to_transforms.py --subset 300 + make_depth_init_ply.py → data/replica_orb_est_ns/
  → ns-train semsplat-replica … → ns-eval / compare_* 脚本
```
- 现成脚本签名（可复用）：
  - `semsplat/data/replica_to_transforms.py --scene <scene> --out <ns> --intrinsics-file frames/intrinsic/intrinsic_color.txt [--subset N]`
  - `scripts/make_depth_init_ply.py --scene <scene> --ns <ns> --n-frames N`（读 scene 位姿+depth 反投影→points3d.ply 并写 `ply_file_path`；默认体素 0.02）。
- 约定工具：`scripts/orb_slam/common.py` = TUM 解析 / 四元数→R / `orb_to_gl_c2w` / `rigid_align`(Umeyama SE3, 强制 det=+1)。
- ORB yaml 要点：`Camera1.fx…`、`Camera.fps: 30`(**必须整数**)、`Camera.RGB: 0`(imread 是 BGR)、`Stereo.b/ThDepth`、`RGBD.DepthMapFactor: 1000`(uint16mm→m，内部 convertTo(CV_32F, 1/factor))、`ORBextractor.nFeatures: 1500~2000`。

### 1.3 结果
- ORB-SLAM3 在 Demo 500 帧 **500/500 全部跟踪**（无 lost）；轨迹 8.04 m。
- ATE（`eval_ate.py`，中心对齐 Umeyama）：RMSE 4.1 cm = 0.51%；mean 3.6 cm / max 11.0 cm。
  - ⚠️ 该场景轨迹近似对称，**只用中心对齐**即可；含朝向的 SE3 反而 ~35 cm/25°，勿用其判断好坏。

### 1.4 可视化脚本
- `compare_views.py`：同帧渲染 GT/估计两模型 RGB，输出 `*_ref/_gt/_est/_montage.jpg`（左中右三栏，栏底黄字标注）。
- `compare_semantic.py`：语义 argmax 三栏 + 图例（自动生成 `*_montage_labeled.jpg`、`legend.png`）。
- `semantic_bg.py`：加"背景提示词 / top-score 阈值 / 余量阈值"的背景感知语义图（实验用）。
- `eval_miou_room.py`：room/office 版 mIoU（见 §4）。

## 2 约定问题与 A/B 基线

**现象**：最早 A/B 出现反直觉结果——GT 位姿基线(14.7dB) 反而 < 估计位姿(20.1dB)。逐一排除了：
- 图像不一致（逐字节相同）→ 排除；
- 初始化点云密度(85k/256k/419k) → 稀疏/密集 GT 都 ~14.7，非主因；
- 高斯数（GT~150k vs est~220k）→ est 致密化更多，但不足以解释 5.5dB；
- 含朝向 SE3 对齐残差 35cm/25° vs 中心对齐 2.4cm → 提示两套位姿存在"朝向约定"差异。

**定位（决定性实验）**：把原始 GT pose 也套 `R·diag(1,-1,-1)`（与 est 相同的换算）再训：
- 原始 GT → PSNR ~14.7，depth 初始化 419k 点；
- **flip-GT → PSNR ~19.98，初始化 ~250k 点**（与 est 侧一致）。
→ 结论：**NICE-SLAM Demo 原始 GT pose 的朝向约定与本仓/nerfstudio 期望相反**；历史 demo 基线(~16)一直偏低由此而来。任何 GT vs 估计对比必须用 flip 后的 GT（scene `data/replica_demo_gl`，ns `data/replica_demo_gl_ns`）。

**A/B 终值**（同 300 帧、同 30 帧 eval 集、半分辨率）：
| 版本 | PSNR | SSIM | LPIPS |
|---|---|---|---|
| GT 原始(错误约定) 6k/20k | ~14.7 / ~14.7 | .699 | — |
| flip-GT 6k | 19.98 | .838 | .4525 |
| est(ORB) 6k | 20.14 | .852 | .4466 |
| flip-GT 20k | 20.19 | .843 | .4365 |
| est(ORB) 20k | 20.34 | .855 | .4321 |
逐视图（vis_20k）：est 19.7–21.3、GT 19.9–21.3，互有高低。

## 3 语义教师演进

### 3.1 CLIP patch 起点（`teacher_kind='clip'`，默认）
- 机制：教师=OpenAI CLIP ViT-B/16 的**整图 patch token**(1/16 网格)→visual_projection(768→512)→L2。训练把每高斯 `sem_features[K=32]` 经 ND 光栅化→`feature_head(Linear K→512)`→与教师 patch 网格余弦/ L1/L2；`alpha>0.5` 掩码。代码：`semsplat/teachers/clip_local_teacher.py`、`semsplat/semsplat_model.py`。
- 症状与根因：CLIP 全局对比训练、patch 特征"整片搅浑"，身份错位/Chair 坍缩（chair 常占 58–81%）。
- 实验结论：
  - **提示词工程有效但治标**：单词→描述句（"monitor with black screen" 等）让单类坍缩明显缓解（monitor 误标、chair 一家独大消失），无需重训；"同一色最大连通块占比"0.50–0.60→0.09–0.25。见 `results/orb_ate/semantic_20k_p2`。
  - **K=32→128 无用**（`outputs/sc_k128` 对比，类分布/余量几乎不变）→ 瓶颈不在低维压缩。

### 3.2 LSeg 稠密教师：尝试与中止
- 做法（Feature-3DGS 官方思路）：`semsplat/teachers/lseg/` 从 feature-3dgs 裁剪出 ViT-L/16@384 dense 编码（去 clip 依赖、文本塔占位）；权重 `data/checkpoints/lseg/demo_e200.ckpt`（3.1GB，Google Drive id `1ayk6NXURI_vIPlym16f_RG3ffxBWHxvb`，PL 存档需 `pytorch_lightning` 才能 torch.load）。
- 已解决：载入 0 missing / 0 unexpected；输入需 **32 倍数**（16 倍数→奇网格触发 refinenet skip 尺寸崩）；`activations` 需每 net 独立（否则多教师串扰）。
- **中止原因（硬证据）**：LSeg 512 稠密特征在单帧任意尺寸/头层/多尺度+flip/官方 ADE150 类文本下，对 OpenAI CLIP **base** 文本全部塌成单一类（如 sofa 97–100%、frame120→fountain/computer 类乱象），与文本不对齐；官方 segmentation_metric 同样只做 base 文本×特征 cosine，黑盒无法解释为何官方可行。详见 memory `gs-slam-lseg-attempt`。代码/权重保留作参考，不默认启用。

### 3.3 SuperClip（`teacher_kind='superclip'`，`slic_clip_teacher.py`）
- 机制：SLIC 超像素(n≈150~250, compactness 10)→每块 bbox crop→CLIP 全局向量→逐像素目标=块向量；cell=16 网格。零新权重（CLIP 已缓存），`skimage` 已有。
- 结果（6000 it, est 集；图 `semantic_v2`、`gallery_v2.html`）：不再单类坍缩；wall/floor/ceiling 首次正确当作大背景（帧间 wall 33–94%、floor 26–36% 出现在墙地多的时候）；前景随内容（有椅帧 chair 14–45%）。与 CLIP-20k 同图对照明显更合理。
- 局限：SLIC≠物体；bbox crop 带邻居 → 边界对象溢色；top-2 余量仅 ~0.01–0.02（可分性弱）；300 帧教师首次缓存 ~15–20 min（每图 ~1.4s）。
- 探索实验：**按超像素抠成"纯黑背景+对象碎片"喂 CLIP → 更差**（000120 wall93→98；000020 丢失 desk/floor）。证明"要纯对象完整掩码"，SLIC 碎片不满足。

### 3.4 SamClip（`teacher_kind='samclip'`，`sam_clip_teacher.py`）★当前最佳
- 机制：SAM-B（HF `facebook/sam-vit-base`，权重 ~375MB）网格点提示(grid=6，逐点前向)→IoU 过滤(0.86)+贪婪去重→**整对象掩码**；对象 bbox 放大 6% 后在**中性灰(0.5)背景**上抠出对象像素喂 CLIP；对象内像素目标=该对象向量，**背景不监督**（返回 grid + coverage，模型损失 `alpha>0.5 & cov>0.4`）。K=32 默认。
- 单帧验证：凡被完整切出的对象 CLIP 身份都判对（frame120：floor/wall/desk 对；frame280：chair×3~4、floor、wall 对）。代价 5–13 s/图（grid6 约 5s），300 帧首次缓存 ~25–40 min，之后步速正常（缓存后 43–150ms/步）。
- **效果**：top-2 余量 0.017–0.027 ≈ SuperClip 的 1.5–2×、top-score 0.26；**用户肉眼确认显著更准**（`results/orb_ate/gallery_sam_vs_superclip.html`）。局限：召回不稳（密集场景偶漏小对象；grid6 曾漏 monitor/对象少）。

### 3.5 背景类/阈值实验（`semantic_bg.py`）
- 三档：baseline(背景 0%) / 加"empty wall/floor/clutter"背景提示词(68–73% 全判背景) / 余量<0.015 阈值(59–70% 把真对象也删)。
- 证据：top-score 中位 ~0.245、**top-2 余量中位仅 0.01~0.02** → 分数缺对象/背景可分性，硬加背景规则必然过删或漏删。**结论：瓶颈在模型可分性，非后处理；背景类方案搁置**（图在 `results/orb_ate/semantic_bg/{sc_base,sc_bg,sc_thr}`）。

## 4 room_0 / office_0 真值评测与 mIoU

### 4.1 数据与语义 GT
- Dropbox `Replica_Dataset`：`{office_0,room_0,room_1}.zip` 各含 `Sequence_1|2/{rgb(640×480),depth(mm),traj_w_c.txt(900×16),semantic_class/{semantic_class_*,vis_sem_class_*}}`；`semantic_info.zip`=各场景 `info_semantic.json`（`classes`：id→名；GT 像素值即 **class id**，0=void）。
- 亮度：**room0/room1 过曝**（RGB 平均亮度 ~187、16–36% 像素截断>250）→ 建图糊/差；**office0 正常**（亮度 ~64）→ 选 office_0 主推。
- 类别映射（公共字典，id 见 `info_semantic.json`）：sofa76/chair20/table80/desk34/plant44/wall93/floor40/ceiling31。room0 与 office0 均无 desk；office0 另有 monitor52/shelf71/lamp47 未列入。

### 4.2 流程（room0/office0 同套路）
```
Sequence RGB-D(已注册 640×480) → ORB feed → ORB-SLAM3 900/900 帧（~16ms/帧）
→ 每 3 帧抽 300 帧(seq idx 0,3,…,897) 估计位姿 ns 数据集 data/{room0,office0}_est_ns
   + semantic GT 同帧软链 data/…/frames/semantic/<k>.png
→ make_depth_init_ply → SAM 语义蒸馏 6000 it（samclip grid6）→ 抽帧预测 argmax ↔ GT id
→ eval_miou_room.py：逐类 IoU + mIoU（忽略 void 0；desk 缺席自动跳过）
```
- 内参沿用 640×480 K≈(fx577.59,fy578.73,cx318.9,cy242.7)；mIoU 里"GT 属未提示类"的像素按预测者计 FP。

### 4.3 结果
- room_0（6k SAM，抽 25 帧）：mIoU **0.176**；建图 PSNR 19.5–26.8。
  - sofa .206 / chair .023 / table .121 / plant .004 / wall .302 / floor .266 / ceiling .309（desk 无）
- office_0（6k SAM，抽 25 帧）：mIoU **0.188**；建图 PSNR 20.4–28.2（`gallery_office0_map.html`）。
  - sofa .311 / chair .016 / table .103 / plant .000 / **wall .464** / floor .026 / **ceiling .394**
- ⚠️ 上表及 office0/room0 **早前所有重建/语义数字均用了错内参 fx≈577**，已被下述 fx320 修正版取代（见"内参修正"）。office0 原生 **640×480** 本就比最初 Demo 1296×968 低一档。
- **内参修正（关键！）**：用 ATE 判别真内参——对 office0 分别跑 ORB(fx577) 与 ORB(fx320/FOV90) 并与 GT `traj_w_c.txt` 比：**fx577 ATE 0.594 m(3%)、轨迹被拉长到 25.8m；fx320 ATE 0.010 m(0.05%)、轨迹 20.3m≈GT 19.8m** → Dropbox room/office 系列真内参是 **fx=320/FOV90（cx320,cy240，无畸变）**，之前误用 1.8× 是"重建别扭/语义被拖累"的重要原因。重建用正确 K：`data/{room0,office0}_est320_ns`。
- **office0 fx320 结果（新准）**：
  - 6k SAM：重建 PSNR 26.8–34.8（中位~33）；8 类 mIoU **0.300**（sofa.575/table.278/wall.569/ceiling.630）
  - **20k SAM（`outputs/office0_320_sam20k/…/2026-09-04_112828`）：重建 PSNR ≈39 dB；13 类 mIoU 0.206**（chair **.257**、door .247、tv-screen .099、desk-organizer .037、sofa .590、table .314、wall .424、ceiling .657；plant/rug/clock/lamp 极小仍≈0）。语义图 `gallery_office0_sem13_320_20k.html`。
  - 13 类口径比 8 类"公平但更难"（把小而稀有类也平均），mIoU 变低≠变差。
- 灰色"其它类"实验（阈值方案）：fx320·6k 类间余量中位仍仅 0.007–0.009 → margin 阈值一设就灰掉 55–99%（把真对象也盖掉），**全局阈值不可用**；要留"其它/未提示对象"位置应改用**加场景真实类**(方案1)而非阈值。
- 读法：正确内参 + 全分辨率 + 20k 已把 chair/door/table 等救起来；剩余弱类 = CLIP 对"小而杂/稀有/合成域"的固有限制 + SAM grid6 稀疏圈选(每帧 3–7 块，细对象常漏/并块)。

## 6 环境/踩坑速查
- 出网走代理 `http://127.0.0.1:7897`；HF/Dropbox/Drive 下载慢就放后台续传（GPU 空转时别并行占显存）。
- torch≥2.6 `weights_only=True`：凡读 nerfstudio/自存 ckpt 都要补丁；`query_cli.py`、`ns_eval_wrapper.py`、`ns_viewer_wrapper.py` 已内建。
- ORB：`Camera.fps` 整数；`RGBD.DepthMapFactor:1000`；轨迹写运行 CWD；全程跟踪最好一次跑完整序列。
- LSeg ckpt 是 PL 存档 → 需装 `pytorch_lightning` 才能 torch.load。
- SAM-B：HF SamModel 一次只能一个提示组 → grid 点需逐点前向（慢）；`SamProcessor.post_process_masks` 还原原尺寸。
- 训练首轮慢 = 教师首次缓存（LRU 进程内，每 run 重算）：建议做磁盘持久缓存（待办）。
- `ns-train --vis viewer` 训完常驻 → 需 `--vis tensorboard`（自动退出）或手动 kill；长训放后台，完成后会收到通知。
- 显存 8GB：半分辨率日程 `num-downscales 1 + resolution-schedule 100000`；语义 head 后置到池化后避免 [H,W,512] 巨张量。

## 附录B 教师机制 / 背景色选择 / CLIP 身份来源（FAQ 存档）

- **教师如何"知道谁是谁"**：SAM 只做**无类别分块**（"哪一块是一个东西"），CLIP 用**图文对比预训练**的知识命名（"这块像哪句话"）；流程 = SAM 掩码 → 灰底对象 crop → CLIP 512 向量 → 作为该对象上高斯的蒸馏目标 → 查询时与文字向量比余弦。
- **为什么灰底而不是黑底/带背景**：黑底对深色物体有偏置（CLIP 把"黑"当内容）；真实邻物上下文会把身份搅浑（patch/bbox 带邻居 → 溢色）；灰(0.5)≈CLIP 的"空/无信息"填充，最不引入底色偏置。昨天"黑底方案不准"其实是 **SLIC 碎片≠整对象(主因) + 黑底(次因)** 叠加；今天换成 **SAM 整对象 + 灰底** 才让身份准。
- **CLIP 为什么能命名**：4 亿「图↔文」配对 + InfoNCE 对比，把图和它的说明拉到同一向量空间近邻；零样本 = 找哪个候选词向量离图最近。限制：只认得它见过的（稀有/极小/分布外 → 我们 plant/clock/rug 弱）。
